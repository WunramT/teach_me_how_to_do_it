Die drei Fälle

FallHeißtStempel-Beispiel

FPBox ohne echtes Objekt (Fehlalarm)Logo als Stempel erkannt
FNEchtes Objekt ohne Box (übersehen)Blasser Stempel fehlt

„Trifft“ heißt: Die Überlappung (IoU) erreicht eine Schwelle, siehe unten. Im F1 sweep von RF-DETR ist das 0,5. Eine Box darf nur ein Objekt treffen. True Negatives gibt es bei der Detektion nicht (Padilla: Object-Detection-Metrics).

IoU: wann eine Box sitzt

IoU = SchnittVereinigung  ·  Vereinigung = A + B − Schnitt
  • TP, wenn IoU ≥ IoU-Schwelle (RF-DETR prüft „≥“). Darunter wird die Box zum FP und das Objekt zum FN (doppelte Strafe).
  • Eine doppelt so breite Box, die das Objekt ganz enthält, hat IoU = 0,50.
  • Matching: Boxen pro Klasse nach Konfidenz absteigend. Jede nimmt die freie Ground Truth mit dem höchsten IoU. Jedes Objekt wird höchstens einmal vergeben, weitere Boxen darauf sind FP (rfdetr/evaluation/matching.py).

Details in Lektion 3. Quelle: Padilla: Object-Detection-Metrics.

Quelle: Google ML Crash Course. Faustregel: Eine höhere Konfidenzschwelle bedeutet weniger FP und mehr FN, also Precision ↑ und Recall ↓.

Was ein Fehler für die Vollständigkeitsprüfung bedeutet

FPEin fehlender Stempel wird „gesehen“. Das unvollständige Dokument rutscht durch.
FNEin echter Stempel wird übersehen. Das vollständige Dokument wird unnötig angemahnt.

F1 sweep in RF-DETR

  1. 101 Schwellen (0,00 bis 1,00, Schritt 0,01), Matching bei IoU ≥ 0,5.
  2. Pro Schwelle: P, R und F1 je Klasse, dann das Makro-Mittel über die Klassen.
  3. Gewinner ist das höchste Makro-F1. Die Tabelle zeigt dessen F1, Prec und Recall. Die Tabelle pro Klasse nutzt dieselbe Schwelle.

Nicht in der Tabelle: die Gewinner-Schwelle selbst. model.predict() nutzt standardmäßig threshold=0.5, beim ONNX-Export setzt ihr sie selbst. F1 gewichtet FP und FN gleich. Sind Fehlalarme teurer, wähle eine Schwelle nach Anforderung (z. B. „Precision ≥ 0,95“, dann höchster Recall) oder nutze F-beta mit β < 1. Details in Lektion 2.

AP und mAP (COCO-Regel)

  1. Boxen einer Klasse nach Konfidenz sortieren und nach jeder Box P und R rechnen. Das ergibt die Precision-Recall-Kurve.
  2. Glätten: Jeder Punkt bekommt die höchste Precision rechts von ihm.
  3. An 101 Recall-Stufen (0,00 bis 1,00) ablesen. Nie erreichter Recall zählt 0.
  4. AP = Mittel der 101 Werte. mAP = Mittel über die Klassen. AP 50:95 = Mittel über IoU 0,50, 0,55 bis 0,95.

AP bewertet die Rangfolge über alle Schwellen und eignet sich zum Vergleichen von Modellen und Checkpoints. Über die Tauglichkeit entscheiden P und R an eurer Schwelle. Ist mAP 50 hoch und mAP 75 niedrig, werden die Objekte gefunden, aber die Boxen sitzen locker. RF-DETR wählt den besten Checkpoint standardmäßig nach mAP 50:95 (best_model_metric="map"), Alternative ist "mar". Quelle: pycocotools/cocoeval.py (accumulate). Details in Lektion 4.

„Makro“ heißt: zuerst pro Klasse (Stempel, Unterschrift) rechnen, dann den Mittelwert bilden. Die mAP-Definitionen folgen der COCO Detection Evaluation. Dort gilt: „AP“ und „mAP“ meinen dasselbe. Das Verhalten des F1 sweep ist im Quellcode von RF-DETR 1.10.1 geprüft (rfdetr/training/callbacks/coco_eval.py, rfdetr/evaluation/f1_sweep.py).
